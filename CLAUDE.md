# Tartan Dictionary — project notes

Read the global instructions first; this file adds only what is specific to this repo. The
*why* of the project is in [`design/thesis.md`](design/thesis.md) — read it before editing
content.

## What this repo is

The presentation layer for tartandictionary.org — an alpha Hugo site (theme `simpleness`). It
does **not** contain the tartan logic. Parsing, normalisation, classification and SVG/PNG
rendering live in the separate Go engine [`tartan_data`](https://codeberg.org/hum3/tartan_data)
(`tartandb` package + `cmd/import|enhance|export`), which *generates* most of this site's
content. See [`README.md`](README.md) for the architecture diagram.

## Generated vs hand-authored — do not confuse them

| Path | Origin | Rule |
| ---- | ------ | ---- |
| `content/tartans/**`, `variants/**`, `families/**`, `stripes/**`, `patterns/**` | Generated by `tartan_data/cmd/export` | **Never hand-edit.** Change the engine templates and regenerate. |
| `content/posts/**`, `content/about/`, `content/_index.md` | Hand-authored editorial | Edit freely; keep consistent with `design/`. |
| `design/**` | Hand-authored canonical arguments | Source of truth — posts express it, not vice versa. |
| `layouts/`, `themes/simpleness/`, `static/`, `config.toml` | Site machinery | Edit as needed. |

## Conventions

- **`design/` is canonical.** When a post and `design/thesis.md`/`glossary.md` disagree, the
  design doc wins and the post is corrected.
- **Engine is the model authority.** Don't re-specify the EBNF or normalisation algorithm in
  this repo's prose as if it were the source — reference `tartan_data` (`ThreadcountList.Normalised`
  etc.). The `design/` docs are the conceptual view; the code is the contract.
- **Ubiquitous language** in [`design/glossary.md`](design/glossary.md) — sett, stripe, pivot,
  reflective/repeating, palette, normalisation, reduction, pattern, Tartan, Variant.
- UK English in prose; SVG colour-name / hex codes stay as the engine emits them.
- **Front-matter dates:** `date` is the original publish date (when the page first went on the
  website) — never change it; record edits with `lastmod`. The byline shows `date`, plus
  "updated `lastmod`" when they differ. Fold any legacy `created` field into `date`.

## Build & run

`task serve` (Hugo dev server, live reload — heavy, ~10GB resident on the full 28k-page
site; use for layout/template work), `task preview` (build + serve `public/` with caddy,
~30MB — use for content/data work), `task build` (prod), `task check` (build smoke test),
`task clean` / `task rebuild`. Regenerating content is a `tartan_data` task, run from that
repo. `task preview` needs caddy on PATH (`go install github.com/caddyserver/caddy/v2/cmd/caddy@latest`).

## Known wrinkles (see ROADMAP)

- `tartan_data/cmd/export` writes to a **hardcoded, now-stale path**
  (`…/major_projects/tartan-dictionary/…`); fix in engine Phase 3 before regenerating.
- This repo's git **remotes are non-standard**: only `origin` → GitHub. Convention wants
  Codeberg `origin` + GitHub `github` mirror (Phase 7; needs the Codeberg repo first).
- No tartan images on generated pages yet — the engine renders SVG but it isn't wired into the
  templates (Phase 4).
