TTD renderer approaches — a comparison harness

Issue #47 asks us to collapse the dual renderer (static pages in Go, dynamic pages re-implemented in JS) onto one Go WASM renderer. Two ways to reach that engine in the browser; this page renders the same sett both ways so the trade-offs are concrete. Both read the palette from the same internal/render code — the point of the exercise.

Approach B
Page WASM — Go renders, JS injects

The wasm runs in the page. JS calls renderSett/renderPalette and injects the HTML; a jog calls applyShade and re-renders in place — no network.

Approach C
Service worker — Go renders in the SW

The wasm runs in the service worker. The image is an ordinary <img> the SW answers; the palette is fetch('/x/ttd?s=…') the SW renders and the page swaps in. A jog is another request (htmx-style).
